# StoryForge 私人创作工作台

当前正式主路径是本地“项目库 -> 生成 -> 编辑 -> 校验 -> 快照 -> 预览/导出”。它面向单一作者，不需要登录，也不提供公共分享安全承诺。

## 安装与配置

1. 使用 Node.js 24 和 npm，执行 `npm ci`。
2. 复制 `.env.example` 为 `.env.local`，再配置 `SQLITE_DB_PATH`，默认是 `./data/storyforge.sqlite`。
3. 配置 OpenAI-compatible 文本模型：`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。火山方舟 Agent Plan 可使用 `https://ark.cn-beijing.volces.com/api/plan/v3` 和已开通的 `doubao-seed-evolving`；变量名保留 `OPENAI_*` 是因为客户端采用 OpenAI 兼容协议。密钥只保留在本地环境文件，不会进入项目备份或 HTML 导出。
4. 执行 `npm run dev`，默认只监听 `127.0.0.1:3000`。
5. 普通 JSON 写接口限制为 512 KB，图谱整图写入限制为 8 MB；项目备份导入单独限制为 8 MB。超过限制时请缩小输入或拆分备份，不要反复重试同一个超大请求。

自动化测试使用 `GENERATION_PROVIDER=fake` 的固定占位 provider，返回成功不等于真实模型质量通过。手工创作应使用默认的 `openai` provider；若页面显示“测试占位模式”，请先停止当前服务并移除该环境变量后再开始正式评估。

## 创作闭环

1. 新建项目并填写简报。
2. 默认进入“分支写作”：模型生成开场，作者每幕选择一个方向，模型只生成被选中的下一幕，达到有限回合后负责剧情收尾。
3. 需要一次性生成完整结构时，进入“高级：一次性结构化生成”；该模式仍支持暂停、恢复和重试。
4. 在编辑器中修改节点正文和选择，人工改写不会被模型静默覆盖；自动保存会合并短时间内的字段变更并串行提交，保存响应不会覆盖请求期间继续输入的新内容。
5. 在发布检查中重新验证当前修订，处理阻断问题，必要时关闭 warning。
6. 创建不可变快照，再使用预览或下载离线 HTML。

## 分支写作

在项目的默认“分支写作”入口中，StoryForge 只生成当前一幕和下一组选项；每次选择都会把选择结果交给已配置的文本模型，再生成下一幕，不会一次性展开未选择的分支。每个活动场景默认提供 3 个有差异的选择，模型输出受 2-3 个选择的契约约束。短篇项目默认在 8 幕内收束，最后一幕不再显示选择按钮。互动回合策略为：极短篇 6 幕、短篇 8 幕、中篇 16 幕、自定义 8-40 幕；如果项目节点预算不足以容纳目标结局，系统会自动缩短互动路径，为后续作者补结局预留空间。

- 互动进度会保存在本地 SQLite，并在浏览器 `localStorage` 中保存当前会话指针。首幕和每次下一幕会先返回“生成中”会话，模型在后台生成，页面会自动轮询并恢复结果，不需要长时间等待请求或手动刷新。
- 刷新或重新打开互动页面会恢复上一次会话；不要在恢复提示出现时重复点击开始。
- 走到结局后点击“保存为正式故事草稿”，系统会创建新的 `review_required` 草稿版本并切换项目当前草稿；原草稿版本会保留，不会被覆盖。
- 已完成或取消的生成流程点击“新建生成”时，也会先创建新的隔离草稿版本；上一版保留在版本链中，新的生成只写入新版本。
- 落稿只包含作者实际选择的线性主线路径，不会伪造未生成的分支；进入编辑器后可继续补充分支、结局和质量校验。
- 在编辑器选中非结局节点，可以使用“新增作者分支”补充一段分支场景。需要收尾时，默认使用“新增作者结局”：输入一句结局方向（也可以留空），点击“让大模型生成结局”，先检查模型给出的标题、选择文案、正文和收束摘要，再点击“采用并保存”。模型预览阶段不会写入图谱，只有确认后才会以当前修订号执行一次整图写入；草稿在生成期间发生变化时会要求重新生成。完全控制结构化字段时，再展开“手动填写（高级）”。新节点状态为 `review_required`；达到项目节点或结局上限时不能新增，结局节点不能继续新增。
- 互动记录会保存在本机，可在页面底部恢复或删除旧会话；已落稿版本不会因为删除互动记录而被删除，“重新开始”也不会静默删除已有记录。
- 如果浏览器在生成期间关闭，重新打开后会先显示生成中状态；模型请求默认允许 180 秒，互动会话会覆盖最多 3 次请求并留出缓冲，默认约 10 分钟后才会被视为中断并释放当前选择，之后可以重新选择。
- 超时、网络、限流和模型结构化输出漂移会进行有限重试；鉴权错误不会重试，结构仍然无法校验时才会显示失败。火山方舟的 `doubao-*` 结构化请求默认关闭 extended thinking，以缩短互动分支响应时间；可通过 `OPENAI_TIMEOUT_MS` 调整模型客户端超时，但必须给本地模型服务留出足够的生成时间。
- 当前分支写作是私人本地体验，不提供登录、多用户隔离或公开分享能力。

## 备份

- 项目库中的“备份”下载 `storyforge-project@2` JSON，可在项目库“导入备份”中恢复为新项目；旧版 `storyforge-project@1` 仍可导入。
- 项目备份包含故事结构、版本、验证状态、非敏感生成统计和互动会话历史；不包含 API key、原始 prompt、原始模型响应或租约。
- 数据库迁移前会自动生成并校验 SQLite 备份；也可以执行 `npm run db:authoring:backup` 手动生成一份。

## 安全边界

默认启动只允许本机访问。只有明确设置 `STORYFORGE_ALLOW_LAN=true` 并配置非 loopback host 时才会警告后启动；这不代表应用具备多用户隔离或公开部署安全性。

页面和 API 默认带有防 MIME 嗅探、防嵌入、来源策略、权限策略和动态 nonce CSP。生产 CSP 不放开 `unsafe-eval`；开发环境仅为 Next 热更新保留必要的开发例外。文本-only 版本不配置远程图片源，也不允许固定局域网来源。

## 可访问性

- 页面支持浏览器缩放，移动端不通过 viewport 禁止放大。
- 生成、保存和错误状态使用可读的 `status`/`alert` 区域；编辑器大纲支持键盘方向键导航。
- 系统开启“减少动态效果”时会关闭页面动画和过渡。
- CI/E2E 会用 axe 检查新建、项目库、生成、编辑器和分支写作页面的 critical/serious 问题；发布前仍需要人工检查键盘顺序、焦点可见性、中文朗读和移动端视觉布局。

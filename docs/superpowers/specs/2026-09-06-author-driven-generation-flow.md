# StoryForge 作者驱动生成流程规格

## 目标

让项目默认进入作者亲自推进的分支写作流程：模型生成开场和有限选项，作者每轮选择一个方向，模型只生成被选中的下一段，达到回合上限后由模型生成结局并落稿。现有一次性结构化生成能力保留为高级入口。

## 用户可见流程

1. 创建项目后进入“分支写作”主入口。
2. 模型生成一段开场正文和 3 个有实质差异的选择。
3. 作者选择一个选项；系统记录选择，只为这个选项生成下一段和下一组选项。
4. 页面显示当前回合、生成状态、已选方向和可恢复的本地会话。
5. 达到项目规模对应的有限回合数后，模型必须解决主冲突，生成无选项结局。
6. 作者确认“保存为正式故事草稿”，系统将已选择路径写入新的 `review_required` 草稿版本并进入编辑器。

## 边界与一致性

- 默认每幕 3 个选择；模型输出最多 3 个，活动场景至少 2 个。
- 不预生成未选择的分支，不把未选择内容写入正式图谱。
- 回合数由项目规模限制，当前短篇为 8 幕；流程不得无限生成。
- 只有已结束会话可以落稿，落稿请求必须幂等。
- 互动生成失败时保留当前场景，释放本轮选择锁，作者可以重试；失败不得破坏已保存路径。
- 模型请求超时必须归类为可重试的 `TIMEOUT`；重试次数有限，不能形成后台无限循环。

## 稳定性要求

- OpenAI-compatible 客户端超时通过 `OPENAI_TIMEOUT_MS` 配置，默认 180 秒。
- `Request timed out`、`timeout`、`deadline exceeded` 等消息即使没有标准错误码，也必须识别为 `TIMEOUT`。
- 互动会话的过期回收阈值必须覆盖最多 3 次模型尝试并留出恢复余量；按默认 180 秒请求超时计算为 600 秒。
- 页面在生成中显示恢复状态；生成失败显示可理解的错误，并允许再次选择或重新开始。

## 保留能力

当前 `GenerationProgress` 的 brief、bible、outline、graph、节点内容和连续性审阅管线保留，迁移到“高级：一次性结构化生成”入口，不再作为默认作者流程。

## 验收标准

- 超时消息被归类为 `TIMEOUT` 并进入有限重试策略。
- 项目主生成入口显示“开始分支写作”，而不是批量生成阶段列表。
- E2E 使用 fake provider 验证开场、至少两次选择、刷新恢复、结局、落稿和进入编辑器。
- 结构化批量入口仍可打开，原有批量生成测试保持通过。
- `npm run typecheck`、`npm run lint`、`npm test`、`npm run build` 和 `npm run test:e2e:authoring` 通过。

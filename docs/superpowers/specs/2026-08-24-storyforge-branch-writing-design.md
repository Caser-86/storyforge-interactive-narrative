# StoryForge 分支写作落稿设计

## 目标

把当前逐幕生成的互动流程从“试玩/会话记录”升级为作者实际走一条选择路径的“分支写作”流程：模型每次只生成当前场景和下一组选项，作者选择后才生成下一幕，最终由模型生成收束场景；完成后可将这条已选择路径写入正式故事草稿图谱。

## 用户流程

1. 作者从编辑器进入“分支写作”。
2. 系统生成开场场景和 2-3 个选择，不预生成未选择的分支。
3. 作者每次选择一个动作，系统只生成该动作的直接后果和下一组选项。
4. 达到预设回合后由模型生成无选项的结局场景。
5. 作者点击“保存为正式故事草稿”，系统创建一个新的 draft 版本，不覆盖原草稿，并自动切换项目当前草稿到新版本。
6. 新版本保留作者实际选择的线性主线，状态为 `review_required`；编辑器支持补充未生成分支、创建作者结局和完成质量校验。

## 数据与一致性

- `interactive_sessions.materialized_version_id` 记录会话与正式草稿版本的唯一关联。
- 同一会话重复保存必须返回已有版本，不能创建重复草稿。
- 只有 `ended` 会话允许落稿；未完成、失败或不存在的会话不得改变正式草稿。
- 原 active draft 作为新版本的 `source_version_id` 保留，历史版本不删除。
- 互动会话删除只删除会话历史，不删除已经落稿的故事版本。
- 项目备份导出和导入必须保留该关联，旧备份缺少字段时按 `null` 兼容。

## 图谱映射

- 每个互动回合对应一个故事节点：首幕为 `start`，中间幕为 `scene`，收束幕为 `ending`。
- 相邻回合之间仅创建作者实际选择的 `main` 边；不把未选择的选项伪造成已生成内容。
- 节点正文、标题和摘要来自对应场景；边标签、意图和后果来自上一幕被选择的选项。
- 版本固定为 `review_required`，因为单一路径尚不满足项目要求的节点数、分支数或结局数时，必须经过编辑器补全和校验。
- 互动路径回合数不得吃满项目节点预算，必须为目标结局预留节点空间；不足时按项目节点预算缩短路径。

## 错误与恢复

- 落稿请求失败不改变会话状态，也不留下半个版本。
- 重试使用会话关联保证幂等。
- 前端展示“已保存为正式草稿”和进入编辑器的链接；未落稿的会话仍可恢复和导出。

## 验收标准

- 单元测试覆盖路径映射、缺失选择、非连续回合和结局校验。
- 仓储测试覆盖新版本创建、旧版本保留、重复请求幂等、未结束会话拒绝。
- API 测试覆盖项目隔离、成功响应和错误响应。
- UI 测试覆盖结束后出现落稿按钮、成功后显示编辑器入口和错误提示。
- E2E 使用 fake provider 亲自逐幕点击选择，结束后保存草稿，新增第二个作者结局，完成结构校验并创建正式快照。

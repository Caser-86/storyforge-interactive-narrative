# StoryForge 本地互动故事创作平台设计

状态：已批准设计

日期：2026-08-19

## 1. 背景与结论

StoryForge 当前是一个以“输入灵感、即时生成首幕、玩家选择后继续调用模型”为中心的互动叙事原型。它已经具备 LLM 接入、故事状态、SQLite、分享、导出、测试和基础观测，但核心数据模型仍围绕运行中的游戏会话，而不是可编辑、可审查、可版本化的作者作品。

本次改造将产品定位收敛为：

> 面向独立小说作者的单人、本地、零登录互动故事创作工具。AI 自动生成有限、完整、可闭环的互动故事草稿，作者在本地编辑、校验、试玩，并导出可离线游玩的单文件 HTML。

产品不追求无限续写。每部作品必须有明确入口、有限节点、可达结局和完成状态。正式程度来自完整创作闭环、可靠数据、可解释生成过程、稳定导出和可验证质量，而不是多用户或功能数量。

## 2. 目标

首个正式版本必须让作者完成以下闭环：

1. 创建本地作品并填写创作简报。
2. 选择作品规模并一键生成完整故事草稿。
3. 查看生成阶段、进度、失败原因和模型消耗。
4. 在大纲树中浏览章节、节点、分支和结局。
5. 编辑正文、选择和跳转关系，或对单个节点发起 AI 重生成。
6. 运行确定性结构校验和 AI 内容审校。
7. 在与导出运行时相同的试玩器中走通故事。
8. 创建不可变版本快照并导出独立 HTML。
9. 备份和恢复完整 StoryForge 项目。

## 3. 非目标

首版明确不包含：

- 登录、注册、邮箱验证、云同步或账号恢复。
- 多人协作、审核流程、组织和权限系统。
- 作品广场、搜索、点赞、评论、关注和付费。
- 图片、音频、BGM、Redis、BullMQ、对象存储和资源 worker。
- 公网托管、在线阅读服务和公开作者后台。
- 循环剧情、运行时无限续写和玩家即时调用模型。
- 桌面安装包、自动升级和跨平台原生集成。
- 游戏引擎导出、插件系统和开放 API。
- 超过 80 个剧情节点的长篇作品。

这些能力只能在文本创作闭环稳定后作为独立项目评估，不进入首版基础架构的关键路径。

## 4. 产品原则

### 4.1 有限且完整

首版故事图必须是有向无环图。允许分支、汇合和多个结局，但不允许循环边。所有从入口出发的有效路径都必须在有限步数内到达结局。

### 4.2 结构正确性由程序保证

入口、可达性、环、断头分支和结局可达性由确定性算法校验。LLM 不负责决定结构是否有效，只负责规划、写作和语义审校。

### 4.3 生成过程可恢复

完整故事生成不是一次长请求。每个阶段和节点任务均持久化，应用退出、网络失败或模型限流后可以从最近成功阶段继续。

### 4.4 不伪装成功

真实模型调用失败时，生成任务进入暂停或失败状态并显示原因。系统不得用固定模板正文替代失败结果，也不得把部分故事标记为完整草稿。

### 4.5 不静默覆盖作者内容

作者修改过的内容受到保护。AI 重生成先产生候选版本，作者确认后才应用。上游变化只会将相关下游节点标记为“需复查”，不会自动覆盖正文。

### 4.6 试玩与导出一致

本地试玩器和导出 HTML 使用同一份故事运行时核心和同一版本快照。试玩通过的版本不得在导出时发生第二次内容转换或调用模型。

## 5. 作品规模

新建作品时提供以下规模选项：

| 规模 | 剧情节点 | 结局 | 用途 |
| --- | ---: | ---: | --- |
| 微型 | 8-15 | 2-3 | 快速创作和验证想法 |
| 短篇 | 15-30 | 3-6 | 默认选项，首版主要体验 |
| 中篇 | 40-80 | 5-10 | 分批生成和较复杂分支 |
| 自定义 | 8-80 | 2-10 | 作者调整章节数、节点目标、分支密度和结局数 |

规模是硬预算，不是提示文本。分支图超过上限时必须在正文生成前停止，并要求压缩结构或修改规模。首版不支持超过 80 个节点的作品。

## 6. 系统架构

系统在当前 Next.js 仓库内渐进替换创作核心，保留可复用的 DeepSeek 客户端、输入安全、Zod 契约、SQLite、测试框架和基础 UI 技术。现有即时游戏流程在新闭环稳定前保留，但新模块不得依赖旧会话模型。

### 6.1 作品工作区

负责作品列表、创建、复制、归档、删除、设置、草稿状态和当前版本。工作区只服务本机单用户，不建立账号概念。

### 6.2 生成编排器

将完整生成拆成可持久化阶段，按依赖顺序调度 LLM 请求。它只编排任务，不直接包含 prompt 文本、数据库 SQL 或 UI 状态。

### 6.3 故事存储库

封装作品、版本、章节、节点、连线、生成运行和校验问题的事务读写。API 层不得直接拼接跨领域 SQL。

### 6.4 故事图校验器

接受一个不可变故事图快照，返回结构化问题列表。校验器是纯领域逻辑，不访问数据库、不调用 LLM，必须可通过固定 fixture 完整测试。

### 6.5 内容审校器

使用规则和 LLM 检查角色、时间线、伏笔、选择差异、节奏和结局质量。它产生建议，不修改正文，也不替代结构校验器。

### 6.6 试玩运行时

读取固定版本的节点和边，维护当前节点和已走路径。首版不执行模型请求、不允许动态图修改，也不依赖编辑器状态。

### 6.7 导出器

将已通过结构校验的版本快照、运行时、样式和故事数据写入单个 HTML。导出器必须确定性运行：相同版本输入产生语义等价的输出。

### 6.8 本地任务执行器

从 SQLite 领取待执行生成步骤，使用租约和心跳防止重复执行。首版同一时间只运行一个作品生成任务，节点正文阶段最多并发两个模型请求。应用重启后，过期租约转为可恢复状态。

## 7. 领域模型

新模型与现有 `game_sessions`、`scenes`、`choices` 分离，避免旧运行时语义污染作者作品。

### 7.1 `projects`

- `genre`

- `status`：`draft`、`generating`、`ready`、`archived`
- `active_draft_version_id`
- `settings_json`
- `created_at`
- `updated_at`

### 7.2 `story_versions`

- `project_id`

- `canon_json`
- `created_at`
- `sealed_at`

快照一旦封存，章节、节点和边不可修改。恢复旧版本通过复制为新的草稿完成，不解封旧快照。

- `content_status`：`planned`、`generated`、`author_edited`、`review_required`
- `author_modified`
- `content_revision`
- `created_at`

### 7.8 `generation_candidates`

局部重生成不得直接覆盖作者正文。候选记录包含目标节点、基于的内容修订号、候选正文、模型信息和创建时间。只有当目标修订号仍匹配且作者确认后才能应用。

## 8. 故事图不变量

每个可试玩或可导出版本必须同时满足：

1. 恰好存在一个 `start` 节点。
2. 至少存在一个 `ending` 节点。
3. 所有节点和边属于同一版本。
4. 每条边的源和目标节点均存在。
5. 图中不存在自环或任何有向环。
6. 所有节点均可从入口到达。
7. 每个非结局节点至少有一条出边。
8. 结局节点没有出边。
9. 从每个可达节点都至少能到达一个结局。
10. 同一节点下选择标签不可为空或重复。
11. 所有节点标题和正文均满足最小内容要求。
12. 节点数和结局数不超过作品规模预算。

任何一项失败都会产生 `blocking` 问题并禁止封存正式快照和导出。

## 9. 完整生成流水线

### 9.1 创作简报规范化

将作者输入转换为结构化简报，包括题材、主题、基调、视角、分级、规模和硬性要求。输入安全检查在此阶段执行。

### 9.2 世界观与人物档案

生成世界规则、背景、主要角色、角色目标、关系、禁止矛盾的事实和核心冲突，保存为 `story_bible_json` 和 `canon_json`。

### 9.3 故事总纲

生成章节目标、角色弧线、主题推进、主要转折、伏笔与回收点，以及候选结局。总纲描述叙事职责，不包含最终正文。

### 9.4 分支图规划

生成完整节点和边的结构化计划，包括节点目标、选择意图、后果摘要、汇合点和结局。此阶段必须严格遵守规模预算。

### 9.5 结构预检

在生成正文前运行故事图校验器。结构失败时暂停任务并显示具体节点或边，不继续消耗正文生成 token。

### 9.6 节点正文生成

按照拓扑层级生成正文。每个请求只携带：

- 创作简报和必要风格约束。
- 世界观与相关角色档案。
- 当前章节目标。
- 当前节点目标和出边选择。
- 所有前置路径共有的事实。
- 必要的前置节点摘要。

不得把整部已生成正文反复放入每个请求。节点输出必须经过 Zod 契约校验后才能持久化为成功步骤。

### 9.7 连贯性审校

全部正文生成后，按章节和全局两个层级检查角色事实、时间线、地点、伏笔、选择差异、节奏和结局。审校只创建问题，不自动改写正文。

### 9.8 草稿就绪

所有节点成功且不存在结构阻断问题后，作品进入 `review_required`。作者解决或确认质量提醒、完成试玩后，才能创建正式快照。

## 10. 编辑语义

编辑器使用三栏布局：

- 左侧：章节、大纲树、节点、分支和结局状态。
- 中间：标题、正文和选择编辑器。
- 右侧：节点目标、前置事实、角色、校验问题和 AI 操作。

节点状态必须在树中可见：未生成、已生成、作者已修改、需复查、存在阻断问题、存在提醒。

以下编辑会触发依赖影响：

- 修改正文：仅增加当前节点修订号，不自动影响结构。
- 修改节点摘要、目标或选择后果：将所有可达下游节点标记为 `review_required`。
- 修改边目标：立即重新运行结构校验，并将新旧影响范围内节点标记为需复查。
- 删除节点：必须先处理所有入边和出边，禁止产生悬空边。
- 局部重生成：创建候选内容，通过对比界面由作者应用或丢弃。
- 恢复快照：复制快照为新的草稿，不修改历史版本。

编辑器必须自动保存。保存失败时保留页面内未保存内容并明确提示，不允许显示虚假的“已保存”。

## 11. 质量门

### 11.1 阻断问题

- 故事没有唯一入口或没有结局。
- 存在循环、孤立节点、无效边或断头分支。
- 存在无法到达结局的有效路径。
- 节点、选择或结局缺少必填内容。
- 生成任务未完整结束。
- 数据结构损坏或版本跨越引用。
- 节点或结局数量超过规模上限。

### 11.2 质量提醒

- 不同选择导向或后果高度相似。
- 角色设定、时间线、地点或世界规则冲突。
- 伏笔、人物弧线或主要冲突未回收。
- 分支深度明显失衡。
- 节点正文重复或节奏失衡。
- 结局过于相似，或部分结局路径显著失衡。
- 汇合节点引用了并非所有前置路径都成立的事实。

作者可以处理或驳回提醒。阻断问题不能驳回，必须修复后重新校验。

## 12. 试玩运行时

试玩器输入是一个版本快照，输出是当前路径状态。首版状态仅包括：

- 当前节点 ID。
- 已访问节点序列。
- 已选择边序列。
- 是否到达结局。

试玩器支持重新开始、回退一步和从编辑器跳转到指定节点进行调试。直接跳转仅用于作者调试，不计为完整路径验证。

运行时不包含变量、条件边、模型调用或动态节点生成。自动化完整路径测试应枚举所有从入口到结局的路径；当路径数量超过测试安全阈值时，至少覆盖每个节点和每条边一次，并单独验证图不变量。

## 13. HTML 导出

默认导出一个独立 HTML 文件，包含：

- 经过转义的故事 JSON 数据。
- 版本元数据和作品标题。
- 无外部依赖的 CSS。
- 无外部依赖的故事运行时 JavaScript。
- 重新开始、回退和本地阅读进度。

导出约束：

- 不发起任何网络请求。
- 不包含 API key、原始 prompt、生成日志或作者内部备注。
- 不执行作者输入的 HTML 或脚本；首版正文按纯文本处理。
- 阅读进度存入以作品 ID 和版本号命名的 `localStorage` 键。
- 导出前必须基于新创建的不可变快照再次运行结构校验。
- 导出器必须有浏览器级 E2E：独立打开文件，完成至少一条路径，并验证离线运行。

项目备份使用带版本号的 StoryForge JSON 格式，包含作品、版本、章节、节点、边、生成元数据和校验状态，但不包含 API key。导入前进行 schema 校验，导入过程在单个事务中完成。

## 14. 本地运行与安全边界

应用默认只绑定 `127.0.0.1`。不提供登录的前提是作者后台不能暴露到公网或不可信局域网。若用户手动改为监听 `0.0.0.0`，启动时必须显示明确风险警告。

本地配置负责保存 DeepSeek API 地址、模型名和密钥。密钥仅在服务端进程使用，不返回给浏览器、不写入数据库、不进入导出和项目备份。

首版删除新创作路径对 Redis、图片 provider 和对象存储的依赖。旧图片代码在迁移期间保持关闭，最终从默认构建路径移除。

## 15. 错误处理与恢复

### 15.1 LLM 错误

超时、限流、认证、网络、空响应和 schema 错误使用不同错误码。可重试错误使用有上限的指数退避；认证和配置错误立即暂停，等待用户修改配置。

### 15.2 应用退出

运行中的任务通过租约识别异常退出。应用再次启动后将过期任务标记为 `paused`，作者确认后继续，不自动重复全部生成。

### 15.3 数据库错误

SQLite 适配层不得吞掉 SQL 异常或返回伪造空结果。写操作使用事务；迁移失败时停止启动并显示备份路径和实际错误。

### 15.4 部分生成

成功步骤保持成功状态。重试只执行失败步骤和明确失效的下游步骤。作者可取消运行，已生成内容保留在草稿中并标记为不完整。

### 15.5 自动备份

数据库在 migration 前创建备份，并按保留策略维护最近备份。手动项目备份是独立能力，不能替代数据库级备份。

## 16. 可观测性与成本

本地状态页展示：

- 当前和历史生成任务。
- 每阶段耗时。
- 模型请求次数、重试次数和失败原因。
- 输入、输出和总 token。
- 按作品汇总的估算成本。
- 节点平均生成耗时和 P50/P95。

统计数据持久化到 SQLite，不使用进程内数组作为唯一数据源。成本估算价格通过本地配置提供；无法确认价格时只显示 token，不显示误导性的金额。

## 17. 测试策略

### 17.1 单元测试

- 图环检测和拓扑排序。
- 唯一入口、节点可达性和结局可达性。
- 规模预算和边完整性。
- 下游失效范围计算。
- 快照不可变性。
- HTML 数据转义和密钥排除。

### 17.2 集成测试

- SQLite migration 从空库初始化和重复执行。
- 草稿保存、快照、恢复和项目导入事务。
- 任务领取、租约过期、暂停、继续和幂等重试。
- 局部重生成候选在修订冲突时拒绝应用。
- 应用重启后恢复未完成生成任务。

### 17.3 模型契约测试

每个生成阶段使用固定 provider 响应测试 request schema、response schema、错误分类和重试行为。CI 不调用真实付费模型。

真实 DeepSeek 冒烟测试是显式手动命令，只生成最小 fixture，并在运行前显示预计调用次数。

### 17.4 端到端测试

完整覆盖：

1. 新建微型作品。
2. 使用固定模型响应生成完整草稿。
3. 编辑一个节点和一条选择。
4. 产生并解决一个结构阻断问题。
5. 创建版本快照。
6. 从入口试玩至结局。
7. 导出 HTML。
8. 在无 StoryForge 服务和无网络条件下打开 HTML 并完成故事。
9. 导出项目备份，删除测试项目，再导入恢复。

## 18. 渐进迁移与交付阶段

### 阶段 0：工程基线

统一包管理器和运行时版本，恢复 typecheck、lint、单元测试和 build，修复 SQLite 错误吞噬及本地 Redis 默认连接问题。未通过质量门前不开发新领域功能。

### 阶段 1：最小闭环骨架

建立新领域模型、存储库、故事图校验器、手工节点编辑、试玩运行时和单文件 HTML 导出。使用手工 fixture 跑通闭环，不依赖 AI。

### 阶段 2：持久化生成流水线

实现创作简报、世界观、总纲、分支图、结构预检和节点正文生成，支持暂停、失败重试和重启恢复。

### 阶段 3：正式故事编辑器

实现作品库、三栏编辑器、自动保存、节点状态、结构编辑、局部重生成候选和下游复查标记。

### 阶段 4：质量闭环

实现规则检查、AI 内容审校、问题面板、版本封存门和完整路径试玩验证。

### 阶段 5：本地正式发布

完成项目备份与恢复、HTML 离线 E2E、成本页、错误体验、文档和发布清单。新路径达到验收标准后，删除旧即时生成入口和默认图片基础设施依赖。

## 19. 首版验收标准

首版只有同时满足以下条件才可称为正式可用：

- 一个全新本地环境可按文档完成安装和启动。
- 作者可以生成微型、短篇和中篇完整草稿。
- 任意失败阶段可以在不丢失成功结果的情况下恢复。
- 所有可导出作品均满足故事图不变量。
- 作者修改不会被后台生成任务静默覆盖。
- 应用重启后作品、版本、进度和任务状态保持一致。
- 项目备份可在空数据库中完整导入。
- 导出 HTML 不联网、不泄露密钥，并可独立完成故事。
- typecheck、lint、单元测试、集成测试、E2E 和生产构建全部通过。
- 旧即时生成流程不再是新创作闭环的依赖。

## 20. 后续扩展条件

只有首版验收通过后，才按独立设计评估以下方向：

- 图片和音频资源层。
- 条件边、变量和循环剧情。
- 100 个节点以上的长篇生成。
- 桌面应用包装。
- 公网发布和作品阅读站点。
- 登录、同步和多人协作。

扩展不得破坏现有版本快照、离线导出、故事图校验和作者内容保护语义。
